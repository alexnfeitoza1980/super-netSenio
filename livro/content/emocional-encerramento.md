## O que percorremos

Nesta jornada, vimos que uma experiência emocional pode trazer informação sem ordenar uma ação. Notar um sinal, escolher uma palavra, considerar contexto e fazer um pedido são passos distintos. Nenhum deles precisa virar um rótulo sobre a pessoa.

| Para a prática | Para o código |
|---|---|
| Nomear sem concluir a causa (116–117) | `enum`, `record` e validação |
| Criar espaço para responder (118) | opções explícitas com `enum` e `switch` |
| Incluir tarefa e contexto (119) | `DateTimeOffset` e planejamento |
| Escutar sem presumir (120) | perguntas abertas reutilizáveis |
| Conversar com clareza (121) | observação, impacto e pedido |
| Melhorar rotinas sem vigiar pessoas (122) | composição com `record` |
| Revisar sem dar nota (123) | reflexão e escolhas opcionais |
| Integrar e verificar os limites (Lab 13) | console fictício e testes xUnit |

O código organiza informação que alguém escolheu fornecer. Ele não identifica sentimentos, mede inteligência emocional, avalia pessoas ou garante que uma conversa terá determinado resultado.

::: pense Uma pequena tentativa
Escolha, se desejar, uma ação simples: perguntar antes de presumir, combinar uma pausa ou registrar um próximo passo de trabalho. Você também pode não escolher nenhuma prática agora.
:::

- Rode `dotnet run --project codigo/emocional/Emocoes.Console` para ver o exemplo fictício.
- Mude uma frase de demonstração e observe o que os testes protegem.
- Se um tema trouxer sofrimento ou exigir suporte, interrompa a atividade e procure alguém de confiança ou um profissional qualificado. O livro não substitui cuidado especializado.

::: cartas
Sinal :: Informação percebida, não uma explicação completa.
Escolha :: Próximo passo que pode considerar contexto e limites.
Escuta :: Curiosidade sem exigir que outra pessoa compartilhe mais do que deseja.
Revisão :: Oportunidade de ajustar práticas sem classificar pessoas.
:::
